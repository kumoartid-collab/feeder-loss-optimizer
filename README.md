# Feeder Loss Optimizer 22 kV

เว็บแอปสำหรับคำนวณการโอนโหลดระหว่างวงจร 22 kV เพื่อให้หน่วยสูญเสีย (Technical Loss) รวมต่ำที่สุด พร้อม Dashboard และรายงาน PDF

- เป็นไฟล์เดียว: `index.html`
- ไม่ต้องมีเซิร์ฟเวอร์หรือฐานข้อมูล ทุกอย่างทำงานในเบราว์เซอร์ของผู้ใช้
- ผู้ใช้ไม่ต้องสมัครสมาชิก
- ข้อมูลที่ผู้ใช้กรอกไม่ถูกส่งออกจากเครื่อง

## ความสามารถ

- อัปโหลดไฟล์ Excel (.xlsx/.xls) หรือ CSV ผล DIgSILENT โปรแกรมอ่านหัวตารางให้อัตโนมัติ เช่น `ตัวย่อสถานีไฟฟ้า`, `สถานีไฟฟ้า`, `วงจร`, `Peak Load[MW]`, `Peak Loss`, `Loss Factor`
- วางข้อมูลที่คัดลอกจาก Excel ได้โดยตรง หรือแก้ไข เพิ่ม และลบวงจรในตาราง (ลบแล้วกดเลิกทำได้)
- ตั้งเงื่อนไขได้: พิกัดโหลดต่อวงจร ขีดจำกัดการโอนโหลด โหลดต่ำสุด และโอนได้เฉพาะภายในสถานีหรือข้ามสถานี
- แสดงผลลัพธ์ทันที: Load ใหม่, ΔLoad, Loss ใหม่, Loss ที่ลดลง, สรุปรายสถานี, พลังงานและเงินที่ประหยัดได้ต่อปี
- ดาวน์โหลดได้:
  - รายงาน PDF (หน้า Dashboard และตารางรายละเอียด)
  - ผลลัพธ์เป็นไฟล์ CSV
  - ไฟล์แม่แบบสำหรับกรอกข้อมูล
- บันทึกข้อมูลอัตโนมัติในเบราว์เซอร์ เปิดครั้งถัดไปจะเห็นข้อมูลเดิม

## หลักการคำนวณ

- Loss ของแต่ละวงจร = k × P² โดย k = Peak Loss / Peak Load²
- เป้าหมายคือหาค่า min Σ kᵢPᵢ² โดยโหลดรวมของแต่ละกลุ่มต้องเท่าเดิม ภายใต้พิกัดและขีดจำกัดการโอนโหลด
- จุดที่เหมาะสมที่สุดคือเมื่อ 2kᵢPᵢ = λ เท่ากันทุกวงจรในกลุ่ม แก้ด้วยวิธี bisection
- พลังงานสูญเสียต่อปี = Peak Loss × 8,760 × Loss Factor

## การนำขึ้นเว็บให้ทุกคนเข้าใช้ได้ฟรี

### วิธีที่ 1: GitHub Pages (แนะนำ ฟรีและลิงก์ถาวร)

1. สมัครหรือเข้าสู่ระบบที่ https://github.com
2. กดปุ่ม **New repository** ตั้งชื่อ เช่น `feeder-loss-optimizer` เลือก **Public** แล้วกด **Create repository**
3. ในหน้า repository กด **uploading an existing file** แล้วลากไฟล์ `index.html` (และ `README.md` ถ้าต้องการ) เข้าไป จากนั้นกด **Commit changes**
4. ไปที่ **Settings → Pages** ในหัวข้อ **Build and deployment** ให้เลือก Source เป็น **Deploy from a branch** เลือก Branch เป็น `main` และโฟลเดอร์ `/ (root)` แล้วกด **Save**
5. รอ 1–2 นาที เว็บจะออนไลน์ที่ `https://<ชื่อผู้ใช้>.github.io/feeder-loss-optimizer/`
6. เมื่อต้องการอัปเดตเว็บ ให้อัปโหลดไฟล์ `index.html` ใหม่ทับไฟล์เดิมใน repository

### วิธีที่ 2: โฮสต์ไฟล์ static อื่น ๆ

ใช้ได้กับบริการที่โฮสต์ไฟล์ HTML ธรรมดา เช่น Netlify, Cloudflare Pages หรือเว็บเซิร์ฟเวอร์ภายในหน่วยงาน โดยนำไฟล์ `index.html` ไปวางไว้ที่ root ของเว็บ

### วิธีที่ 3: ใช้ในเครื่องหรือแชร์เป็นไฟล์

ดับเบิลคลิกเปิดไฟล์ `index.html` ด้วย Chrome หรือ Edge ก็ใช้งานได้ หรือส่งไฟล์นี้ให้เพื่อนร่วมงานทางอีเมลหรือ LINE ได้เลย
